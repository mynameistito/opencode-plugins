## Why This Matters

The exported JSON Schema is used by editors, but it gives every provider the union of all options. Runtime decoding rejects excess properties, so users can receive valid editor autocomplete for invalid configuration. Make the exported schema mirror each provider's runtime field set and lock the agreement with tests.

## Current State

- `src/config-schema.ts:57-99` defines distinct schemas: Codex accepts `apiKey`, `authPath`, `authorizationScheme`, `baseUrl`; ZAI omits `baseUrl`; Synthetic, MiniMax, and OpenCode GO omit `authorizationScheme`; Qwen has only common display fields.
- `src/config-schema.ts:125-128` decodes with `onExcessProperty: "error"`.
- `usage-limits.schema.json:17-22` references one `$defs/provider` for all six providers; its fields at lines 59-68 therefore over-permit options.

## Steps

### Step 1: Split schema definitions by provider capability

Keep one common display-field definition. Add provider definitions that combine those common fields with exactly the runtime-specific fields. Point each `providers` property to its provider-specific definition. Preserve `additionalProperties: false`, defaults, top-level limits, `$id`, and credential descriptions.

**Verify**: inspect the JSON with `bun -e "JSON.parse(require('node:fs').readFileSync('packages/opencode-usage-limits/usage-limits.schema.json','utf8'))"` -> exit 0.

In `__tests__/config.test.ts`, load the published JSON file and assert the allowed property names for all six provider definitions: Qwen has only common fields; ZAI lacks `baseUrl`; Codex includes both `authorizationScheme` and `baseUrl`. Also retain runtime decoder tests showing an unsupported provider field is rejected. Do not introduce a schema validator only for this test.

**Verify**: `bun --filter @mynameistito/opencode-usage-limits test __tests__/config.test.ts` -> all pass.
